## 官方样例的具体来源

`evaluation/config/aml_official_examples.json` 保存三组请求：

1. 接入契约正文的文字 Add 与带顶层 options 的 Search。
2. API Guide 的文字 Add/Search，保留 `<run_id>` 示例标识和所有其他字段。
3. API Guide 的图文 Add 和图片 Search，保留有序内容数组和顶层 options。

官方图片地址是 `data:image/jpeg;base64,...` 和 `data:image/png;base64,...`，其中
省略号不是合法图片。测试仅将这两个图片占位符替换成生成的有效 JPEG/PNG。
没有把文字改成更容易检索的问答，也没有把选项中的任何一项标记为正确答案。
官方 Search 响应中的示例 ID、内容和分数是结构示意，不要求服务伪造相同返回值。

公网报告只记录检查名称、状态码和耗时，不保存 Key、请求正文、返回证据或真实评测数据。
该测试从另一台开发服务器调用杭州公网 HTTPS，开启证书验证，不使用跳过 TLS 校验的选项。

## 本轮发现并修复的问题

旧逻辑在未知 user_id 或 top_k=0 时提前返回空 data，绕过查询图片和空白文本校验。
四个新增反例先复现为错误的 HTTP 200。现在先验证内容与媒体限制，再判断是否无结果；
非法请求返回 422，且不调用上游模型。原有持久化格式、模型和检索参数不改变。

先在开发机通过回归，再在云端隔离目录通过 73 项测试后部署。部署保留旧代码备份，
仅替换必要代码和测试工具，未删除记忆数据库。重启后健康检查及公网样例通过。

   电脑关机、休眠、断网或代理关闭会影响服务；自动重连不能消除此依赖。

4. 数据清理：有停服后的 purge-user 工具，但没有自动获知平台任务结束及到期清理的机制。
   必须在正式任务结束后 30 天内清理记忆、所有派生缓存和备份，并保留不含载荷的执行记录。
5. 上游供应商：配置中模型名正确不等于独立验证了第三方网关的真实模型或数据处理政策，
   正式发送评测数据前需确认供应商条款符合赛事数据使用边界。
6. 平台验证：取得 Eval Key 后完成正式 Smoke，固定实际部署版本、提交材料，再启动 Full。
