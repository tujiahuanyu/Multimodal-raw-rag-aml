# v1.4：Query 分析与自适应多问题检索

## 流程

1. 对合法、top_k 非零且该用户已有记忆的 Search，先调用一次 `gpt-4o-mini` 分析原始
   Query。输入为原问题、原图（如有）及独立的 options；不读取评测答案或金标。
2. 模型返回严格校验的 JSON：`{"mode":"single","subqueries":[]}`，或
   `{"mode":"decompose","subqueries":["子问题1","子问题2"]}`。
   复杂问题允许 2–4 个不同子问题，每个最多 600 字符；不生成伪答案、不猜缺失实体。
3. single 保持 v1.3 的召回／重排流程和 15 条消息上限；有图时仍单独生成查询图
   caption，并分别用原问题与 caption 检索。此模式唯一新增正常规划请求一次。
4. decompose 除保留原问题／caption 召回外，各子问题也分别向量化检索。
   原问题仍保留在检索和重排输入中，不被拆分结果覆盖。完全相同的检索文本不重复召回。
5. 每路最多 128 个候选，用既有 RRF（k=60）合并去重，最多保留 128 个候选。
   最多 6 路（原问题、查询图 caption、4 个子问题）；每个图片在同路的描述视图仍先聚合。
6. 对融合候选只调用一次重排。复杂模式的重排输入保留原问题、查询图说明及标注为
   “检索子问题、不是答案”的子问题文本，以兼顾不同证据需求。
7. 按重排顺序展开完整原始消息，再按 message_id 去重。single 最多 min(top_k,15) 条，
   decompose 最多 min(top_k,30) 条。媒体预算仍为 30 MiB，超限候选跳过并继续补足，
   不截断原始消息。返回中不注入规划器内容、答案或给平台 Answer 的指令。

历史 Add、原始 caption、每图最多 4 条细节描述索引均不改变。规划器和图片描述共用
现有 VLM 服务与私有配置，均使用 gpt-4o-mini，无需新增 API Key 或下载模型。
规划统计单列为 planner；HTTP 重试仍可能使实际请求次数高于正常的一次。

## 校验与限制

- 子问题会去除首尾空白，按大小写／连续空白规范化去重；去重后不足 2 条则明确报错。
- 拒绝未知模式、额外字段、非字符串、过长子问题、超过 4 条或不完整／截断的 JSON。
  上游错误明确返回 502，不静默假装规划成功后降级为旧流程。
- 每个有效非空 Search 正常进行一次规划，不把规划结果跨用户缓存；空用户、top_k=0
  不调用模型。非法 Query 和图片仍先校验，不因空结果忽略非法输入。
- 只实现“一次分析、独立子问题召回、合并重排”，不是根据第一次检索
  找到的未知实体再搜索的自适应多跳 Agent。依赖缺失桥接实体的问题仍可能失败。
- 不增加答案生成或拒答阈值，不声称该改动自动解决 abstention；更多候选也可能增加噪声。
  需使用公开数据比较证据覆盖率、答案质量、拒答误伤、调用次数和时延。

## 运行

按 README 启动；配置协议升为 4，必须使用新 `--data-dir`，不复用 v1.3 的正式索引或
Full 状态。服务健康版本为 `raw-rag-aml-v1.4`。无需调整原 Add/Search 结构或认证方式。
正式平台需以新版本重新执行 Add；切换前确认无 Full 运行，保留旧服务回退入口。

调用增加：每题正常多一次规划；复杂题最多多 4 条查询向量及对应召回，但仍只重排一次。
原始证据数量可能增加到 30 条，需同时考虑平台上下文预算及接口媒体预算。

## 发布前隔离验证（2026-10-27）

- GPU 开发服务器独立目录下全部 221 项回归测试通过，耗时 20.80 秒。包括直接／拆分
  路由、先分析后查询图描述、独立子查询召回、合并去重、一次重排、15／30 条后置限额、
  top_k、错误响应、输出格式和用户隔离。未修改旧全量实验的代码或 GPU 0 进程。
- 真实 gpt-4o-mini、text-embedding-v4、已有 GPU 1 上的 Qwen3-Reranker-4B 验证了
  公开 Mem-Gallery 场景的 6 个问题，以及额外的 2 个自造问题。
- 公开场景沿用 370 条消息、31 张历史图片的 v1.3 公开实验索引的只读备份副本。
  Add 和索引结构不变，仅在新实验副本上校验旧配置身份后更新实验身份；原索引未修改。
  26 个 Add 批次幂等重放通过。此操作不用于生产；线上发布仍采用新的空数据目录。
- 公开 6 题中 4 题选择 single，各返回 15 条；2 题选择 decompose，各拆 4 个子问题、
  共 5 路召回、返回 30 条。所有结果均为不同原始消息；仍是 5/6 题找全标注证据，
  没有显示该小样例的证据召回提升，也未进行新方法的官方 LLM-Judge。
- 自造单事实／双事实问题分别正确选择 single／decompose。全部 8 次 Search 每次均
  一次逻辑规划、一次本地重排；实际规划 HTTP 尝试 12 次（含重试），向量请求 5 次。
  历史描述和查询图 caption 复用公开实验缓存，新增视觉描述请求为 0。
- 总耗时 499.63 秒，包括模型加载、重试、网络等待和自造问题检查；不是云端吞吐或
  纯规划时延测量。测试确认流程正确，不能据此声称平台关联推理或拒答分数已提升。
