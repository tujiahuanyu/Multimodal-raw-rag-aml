# v1.3：保留传入 caption，补充图片细节视图

## Add

1. 原始文字、传入 caption、图片字节及顺序照常保存并切片，不覆盖、不改写。
2. 同一用户的每张不同历史图片调用一次 `gpt-4o-mini`，一次返回最多 4 条互补短描述。
   关注可见对象／动作、颜色／材质／区分性细节、空间关系／背景、确实能读出的文字；
   不要求凑满 4 条，不猜身份、品牌、日期、所有权或模糊文字。
3. 图片自身的生成描述不依赖原 caption 或问题，避免把文字提示再幻觉成视觉事实。
   同用户相同图片复用缓存；不同用户不共享派生缓存。查询图的 caption 缓存独立。
4. 每条描述独立向量化并写入 `image_views`。相邻传入文本也建立独立视图；
   每个视图明确保存原始消息 ID、图片哈希、provided/generated 类型。
   原始 caption 仍完整保留在原始消息索引中，即使相邻对应关系不明确也不丢失。

API 没有专用 caption 字段，只有有序 text/image_url。对应规则为：连续文本对应其后
连续图片；出现新文本时重新建立对应关系。仅一张图片且没有前置文本时允许使用后置
文本。多图的歧义后置文字只保留在原始消息中，不强行归属到某一张图。

## Search

- 查询中有图片时，仍由我们调用 `gpt-4o-mini` 生成一条查询图 caption（256 输出 tokens
  上限；重复图片使用查询缓存）。不依赖数据集提供查询图 caption。
- 问题原文及 options 为 A 路，查询图 caption 为 B 路；两路都可检索原始 chunk、
  原始 caption 图片视图以及生成细节图片视图。没有查询图片时仅 A 路。
- 每一路同一原始消息中同一图片的各视图取最高相似度，只占一个图片候选位置。
  两路用稳定图片候选 ID 做 RRF（k=60），不会因为生成描述多而多投票；若两路命中
  不同描述，保留两条命中文字供重排参考。原始 chunk 作为独立候选仍保留。
- 最多 128 个融合候选只重排一次，随后展开完整原始消息，按消息 ID 去重后最多 15 条。
  命中生成描述时也返回绑定的原图和原始文字，不把生成内容冒充历史原文返回。

这仍是“图片转文字的多视图检索”，不是 CLIP／SigLIP 式直接图片向量检索。
提示词和格式校验只能减少噪声，不能保证视觉模型不出错；需要独立评测验证收益。

## 运行与边界

使用 README 的启动方式，但必须为 v1.3 指定全新数据目录。旧库不会自动补生成描述，
也不能直接复用；正式评测需由平台重新 Add。不要在运行中的 Full 中切换服务或索引。

每张新历史图增加一次视觉请求（最多 4 条描述在同一次请求返回），以及对应的文字
向量化；视觉请求输出上限 768 tokens、图像 detail=high。无可靠细节可返回空列表，
原始文本／图像仍保留；上游失败或格式错误则明确失败，不假装完成增强写入。
同一请求号重试保持幂等，成功返回前原始记忆、图片及视图在同一事务持久化。

更新线上服务需单独部署，使用全新索引并保留旧版回退入口；实际版本以 `/health` 为准。
历史 Smoke 分数不能作为本方法的结果，公开小样例检索召回也不是官方能力分数。

## 本次隔离验证（2026-10-27）

- GPU 开发服务器的独立目录测试，未修改旧全量实验或阿里云服务。全部回归测试
  190 项通过；格式检查和差异空白检查通过。
- 公开 Mem-Gallery 的 AI_Robotics_Automation_Future_Tech 完整场景：370 条消息、
  31 张历史图，26 批 Add，6 个查询（3 个无图、3 个有图）。原始 caption 建立 31 个
  图片视图，生成描述建立 61 个图片视图，每图实际生成 1–4 条。
- 使用真实 `gpt-4o-mini`、`text-embedding-v4` 和本地 `Qwen3-Reranker-4B`，不是
  云端 Cohere 配置。历史视觉请求实际尝试 34 次（含重试），查询视觉请求 2 次
  （第三个含图查询命中查询缓存）；向量请求 65 次，重排 6 次。
- 6 次 Search 均只重排一次、各返回 15 条不重复来源消息；无图／有图分别走一／两路。
  同图多描述没有在单路重复占图片候选位置。总耗时 421.45 秒，包含模型加载和网络。
- 另做同条件公开数据对照：相同原始消息、传入 caption、缓存查询 caption 与查询向量、
  相同本地重排模型，只把召回切回 v1.2 的原始 chunk 索引。两种流程均有 5/6 题
  找全标注证据轮次，另 1 题均未命中；对照没有额外调用视觉或向量 API。

结论：新增索引和原图／来源绑定已跑通，但这个小样例没有表现出证据召回提升。
未运行本方法的官方 LLM-Judge 或平台 Smoke，不能据此声称比赛分数提高或降低。
