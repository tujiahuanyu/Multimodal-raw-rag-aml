# v1.5：向量近邻关联与一跳扩展

## 方法

在 v1.3 上新增关联，不包含 v1.4 的问题分析／拆分。

1. Add 仍保留原始文字和图片，生成图片细节视图并向量化。
2. 使用已有向量，在同一个 user_id 下为每个检索节点维护余弦相似度最高的 5 个其他节点；排除自身，允许跨 session。图片的多个描述作为同一个图片组节点，节点对相似度取描述视图余弦最大值，避免同图描述重复占关联名额。
3. 新节点不仅获得自己的关联，也更新已有节点的最近邻。追加消息导致 session 重新切片时，删除失效 chunk 的边并补足近邻。
4. 原始记录、chunk、图片视图、关联和幂等记录在同一个 SQLite 事务提交后，Add 才返回成功。关联失败会回滚原始写入；已有派生缓存可能保留，但不会产生半完成的可检索记忆。
5. Search 保持原问题／查询图描述的召回流程，融合最多 128 个候选并只重排一次。
6. 取重排前 15 个节点，每个读取其关联中相似度最高的 2 个节点，仅扩展这一跳。
7. 先合并这些节点，再展开其覆盖的完整原始消息，按原始 message_id 去重；不按内容合并不同的真实消息。
8. 最终不再截回 15 条，但仍不得超过 top_k，并遵守 30 MiB 媒体预算与 128 MiB 响应上限。最多选中 45 个检索节点，并不意味着最多只返回 45 条原始消息。

关联不调用额外的 LLM、Embedding 或重排 API，只复用已有向量。首次建图需要计算向量近邻，Add 的 CPU 与持久化成本增加；批量矩阵计算限制临时内存，增量写入只重新评分新节点和失去近邻的节点，其他旧节点仅与新增节点比较。

## 顺序与分数

- 主节点保持唯一一次重排的顺序。
- 每个主节点严格先取 top-2 关联，再合并去重；如果它们已在前 15 个主节点中，或多个主节点关联到同一个节点，不继续从第 3–5 个关联补位。
- 原始消息去重发生在展开后。不同 chunk 覆盖同一条原始消息时只返回一次。
- 关联候选分数为 `min(末主节点重排分, 父节点重排分 × clamp(关联余弦, 0, 1))`，按分数、关联余弦和稳定节点 ID 排列；共享邻居保留最高衰减分。该分数是排序启发式，不代表第二次模型相关性判断。
- 原始消息继承首次命中节点的分数，所有主节点先于关联节点；重复消息和超媒体预算消息跳过，继续处理本次已选节点，绝不裁切原始消息或图片。
- 相似度相同的关联按节点 ID 降序确定顺序；只维护每节点的有向 top-5，不保证邻接关系对称。

## 部署与兼容性

运行版本为 `raw-rag-aml-v1.5`，配置协议版本为 5，默认 `association_count=5`、`association_expand_count=2`。更改这些设置会改变索引身份。

必须使用新的私有 `--data-dir`，不能复用 v1.3／v1.4 数据库或将旧任务断点视为新版本结果。保留旧库以支持回退；模型配置和最新 Key 不需要随版本回退。

服务器仍按用户隔离，清理用户时同时删除其关联。不能为了复现旧 Smoke 分数跨用户共享图片描述或评测记忆。图片描述仍可能随新的模型调用变化，代码版本相同不等于生成索引快照相同。

本方法扩展的是向量近邻，不是经验证的语义关系图；相邻滑窗、同主题内容或同一来源的不同视图可能占据关联，最终去重也可能使新增结果很少。是否提高多跳能力，需要固定公开开发集、模型与预算做消融，不能由接口测试通过推断。
